## Saved Data

One account-wide SavedVariables table, `FlagUpDB`, kept by AceDB (`Core/Store.lua`): the data in `global`, the settings in one "Default" profile shared by every character. AceDB saves only the values that differ from their defaults. Mail only reaches a character of the same ruleset and faction, so characters and rules are kept apart by ruleset and faction (`"PvP-Alliance"`, `"Normal-Horde"`…). A character works on its own pair's entry: all its rules, with the overrides of all its characters. The settings are account-wide. Characters are named "First Surname", the name the game gives a character on WoW: Forever, unique within a ruleset.

Outside Forever, characters are named "Name-Realm" (the realm normalized, without spaces or "-") and shown without the realm being played. Mail reaches a realm and the realms connected to it, so the households are kept in `realmHouseholds`, by those realms joined in order (`"Medivh-Suramar"`), both factions together; each character saves its faction (a typed one, the faction of the character that typed it), since mail crosses factions only between known characters of one realm. At login, a household saved under some of the realms being played (realms connected since) joins the household being played: its characters are added, and its lines and ignored items too; on a line both have, the household being played keeps its fields, the other's filling those it leaves unset.

```lua
FlagUpDB = {
    global = {
        rulesetFactions = {
            ["PvP-Alliance"] = {
                characters = {            -- recipients, by name
                    ["Lyra Moonfield"] = { typed = false, guid = "Player-4613-00D061FC", faction = "Alliance",
                        class = "MAGE", icon = 136240 },  -- known: logged in with Flag Up; an icon chosen
                    ["Kael Duskwhisper"] = { typed = true, faction = "Alliance", atMailbox = true },  -- typed, shown at the mailbox
                },
                ignored = {               -- never offered at the mailbox
                    all = { [2589] = true },                                -- by item ID: by every character
                    characters = { ["Silvia Ashgrove"] = { [2447] = true } },  -- by name, then item ID
                },
                rules = {
                    categories = {        -- by item class ID
                        [7] = { sendTo = false },                   -- Trade Goods
                        [4] = { sendTo = "Borin Ironhand" },        -- Armor
                    },
                    subcategories = {     -- by item class ID, then subclass ID
                        [7] = { [9] = { sendTo = "Lyra Moonfield" } },                      -- Herb
                        [4] = { [1] = { qualities = { [2] = true, [3] = true, [4] = true } } }, -- Cloth, rule inherited
                    },
                    items = {             -- by item ID
                        [2447] = { sendTo = "Lyra Moonfield", keep = 20, fullStacksOnly = true,
                            overrides = { ["Silvia Ashgrove"] = { sendTo = "Borin Ironhand", keep = 50 } } },
                    },
                },
            },
        },
    },
    profiles = {                      -- AceDB also keeps profileKeys: each character's profile, "Default"
        Default = {
            launcher = { hide = false, showInCompartment = true },  -- LibDBIcon's own format, minimapPos included
            sendAutomatically = false,
            sendKey = "SHIFT",        -- "SHIFT", "CTRL", "ALT" or "NONE"
            uncheckCheap = true,      -- an item worth less than its postage starts unchecked
            uncheckUnpriced = false,  -- an item a vendor won't buy starts unchecked
        },
    },
}
```

- **A household** (a ruleset-faction pair on Forever) gets its entry when its first character logs in; it starts with no rules.
- **A typed character** joins the household of the character that typed it.
- **A renamed character** (the game can force a rename): a known character saves its GUID, which a rename doesn't change. At login, a GUID saved under another name moves that character to its new name, with the rules that send to it, its overrides and its ignored items; where it already had overrides under the new name, the old name's fields win.
- **`ignored`**: the items never offered at the mailbox, created with the first one; `all` for every character of the household, `characters` for one. An ignored item keeps its rule line.
- **A line** is one entry in `rules`, added by the player; it stays until removed. A field the line doesn't set is `nil`: it is inherited from the line above (item → subcategory → category), and above the categories from the defaults (*Don't send*, no quality filter, nothing kept, any amount). A new line sets no field.
- **`sendTo`**: the recipient's name, or `false` for *Don't send*.
- **`qualities`** (Armor and Weapon categories and subcategories): the selected qualities; an empty table means none selected, no filter.
- **`keep`** (items): how many stay in the bags; `nil` takes the default, nothing kept.
- **`fullStacksOnly`** (any line): `true` sends only full stacks of an item that stacks, counted from what is left after `keep`; `false` sends any amount; `nil` inherits, and the default is any amount.
- **`overrides`** (any line): by the overriding character's name, only the fields that character overrides (`sendTo`, `keep`, `qualities`, `fullStacksOnly`, as on the line). The tree marks a line with a glyph when the character being played has an entry in its `overrides`.
- **Not saved**: an item's name, quality, icon and category, read from the game by item ID; category names, read by class and subclass ID; the mailbox checkboxes, which last one run.
